Pattern workflow r2 - replication & scaling

Runs once over the whole review database. It finds approaches that are the same across projects and labels each repeat as replication (another country) or scaling (the same country).

Steps

  1. Semantic match. Each validated approach is represented by its theme and the original text it was extracted from. Every pair of approaches from different projects gets a semantic similarity score (sentence embeddings when sentence-transformers is installed; otherwise TF-IDF, which also reads the approach name and description because lexical matching on the evidence alone cannot find paraphrases).
  2. Reference signals. Same major sector, same category (pillar) and same solution each add a small bonus (+0.03). They are never required.
  3. Verify. Pairs above the threshold (best 5 partners per approach, at most 300 pairs) go to the model, which reads about two pages before and after each evidence sentence in its source document and decides whether both projects use the same approach (confidence ≥ 0.6). Verdicts are cached; re-runs only pay for new pairs.
  4. Same approach. Verified pairs are joined into groups of the same approach (connected components). Projects are ordered by approval date; the first project is the origin.
  5. Replication vs scaling.
Later project in the groupLabel
Country not seen earlier in the groupReplication - the approach travels to a new country
Country already used the approach in an earlier projectScaling - the approach is taken further in the same country

Pair level: a verified pair across countries is a replication link; within one country it is a scaling link. Regional / multi-country projects carry a region name as country and are compared as written.

Without an API key the verification step is skipped and the web app shows the semantic candidates, clearly marked as unverified.
