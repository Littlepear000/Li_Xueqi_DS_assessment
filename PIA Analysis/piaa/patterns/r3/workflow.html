Pattern workflow r3 - replication (confirmed / likely) and scaling, database only

Runs once over the whole review database and reads no documents: every validated approach already carries its evidence passages (up to four), the explicit project references found when it was extracted, and its project's country, sector and approval date. The result is two columns per approach: replication (level + source project) and scaling (source project).

Definitions

ColumnValueRule
ReplicationconfirmedThe approach's passages state directly that the project replicated, applied, used or learned from an approach of an earlier project. The strongest form names that project (P-code or title); a clearly identifiable earlier operation also counts. The source project ID is recorded (inside or outside the portfolio).
likelyThe passages say the approach draws on earlier experience without naming a project, and a closely matching (verified) earlier approach exists in a project of a different country. That project is recorded as the probable source.
ScalingscalingThe same approach (verified by the model) exists in an earlier project of the same country and the same sector. The earliest such project is recorded as the source.

Steps

  1. Build corpus. Validated approaches (rejected / mentioned-only excluded) with their passages, explicit references (replication_json, found by the Approach Spot workflow when it read the full documents), country, sector, FY.
  2. Find cues. Rules scan the passages for replication language (replicate, based on the experience of, modelled on, lessons from ...), scaling language (scale up, nationwide, roll-out ...), P-codes and project names from the project list.
  3. Match earlier approaches. Semantic similarity (sentence embeddings, else TF-IDF) between each approach and the approaches of projects approved before it; same sector / category add a small bonus. The best five candidates are kept.
  4. Judge. One model call per approach that has a cue, a reference or candidates. The model sees the passages, the cues and the candidate list and returns (a) the replication level with the source project / text / verbatim quote and (b) for each candidate whether it is the same approach, with a confidence. Judgements are cached.
  5. Two columns. Rules finish the job: confirmed needs an identifiable source (otherwise downgraded to likely); likely needs a verified same approach in an earlier project of another country (otherwise dropped); scaling needs a verified same approach in an earlier project of the same country and sector. Verified links also form same-approach groups for the charts.
  6. Story tables. By sector, region, country and fiscal year, with confirmed and likely counted separately.
  7. Write. result.json, approaches.csv (the two columns) and the other tables; the columns are also written into the database (approaches.replication_label, approaches.scaling_label).

Cost: one call per approach (about 3-5k tokens), so a full portfolio of a few hundred approaches is a few minutes. Without an API key the model step is skipped and only cached judgements are used.

Limits: only what the passages say is found - a project that reuses a design without saying so appears, at best, as a verified same approach without a link type. Sources outside the portfolio keep their P-code but cannot be checked.
